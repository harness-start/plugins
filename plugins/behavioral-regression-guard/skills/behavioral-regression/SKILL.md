# Behavioral Regression

Turn a known failing behavior into a bounded proof obligation before changing production files.

## Workflow

1. Confirm that the task has an observable expected/actual mismatch. If it does not, diagnose first and return only after a direct reproduction exists.
2. Read [contract.md](references/contract.md) and create one `behavioral-regression/v11` contract at `.behavioral-regression/BR-<stable-id>.json`. The reference and hook findings are the complete authoring interface: do not inspect plugin hooks, validators, acceptance cases, or state storage to operate this workflow.
3. Name the externally observable `surface.publicSeam` and the pre-existing `surface.constraintSeam`: the lowest existing operation that turns original source inputs into output constraints. Record exact source-level invocation fragments in `publicLocator` and `constraintLocator`, and bind `constraintLocator` to the declared production file where it already exists using `constraintSourcePath`. The seams may be the same when that public operation itself forms the constraints. A prospective helper or a higher-level consumer is not the constraint seam. For three-or-more composition, the constraint locator must be callable (contain `(`), so a property read cannot stand in for the combiner it delegates to.
4. Enumerate every supported invocation shape visible in the task, signature, docs, or existing tests in `surface.callForms`. Bind each form to the exact `sourcePath` and a `signatureLocator` that names the same callable as its seam locator and resolves to the complete signature already present in production; shortening `def transform(self, *args)` to `def transform`, or binding `transform(` to a fixed-arity nested helper, does not make it fixed-shape because the hook derives variadic shape from the real callable's complete source signature. When `repairMode` is `extend-existing-seam` and the target intentionally changes a fixed callable to variadic, keep the frozen baseline signature locator and declare every form of that callable `variadic: true`; the field describes the target source signature, not one call site's argument count. After the edit, the loader accepts the missing old locator only when Git confirms one matching fixed baseline declaration and the current source contains one same-level variadic declaration of that callable. Separate independently mutable `dataComponents` from flags, origins, contexts, and other `controlInputs`. A fixed form with two or more data components derives `multi-component`; a source-level rest/variadic form derives `variadic`; otherwise it derives `single`. Never collapse rest arguments, channels, coordinates, contributor positions, tuple fields, or record fields into one conceptual value when callers can vary them independently. Preserve the user's concrete nouns throughout `problem`, `surface`, case dimensions/coverage, and `oracle.assertions`: v10 derives mandatory `ordering` from order/sequence/dependency claims and mandatory `representation` from representation/container/tuple/deduplication/shape claims, including claims that an operation returns or produces a list, tuple, array, or container. Do not move or paraphrase a claim to evade its semantic branch.
5. Declare isolated proof scripts in `scope.verificationPaths` and at least one tracked, production-adjacent project test in `scope.regressionPaths`. In v11, keep `scope.supersededAssertions` as an array. For ordering semantics, declare at least one exact target expectation supersession as metadata while the Git-baseline assertion remains unchanged. For a task with no ordering semantics, use `[]` rather than inventing an unrelated baseline replacement. The isolated managed bundle, not an edit to the project test, supplies the public-seam RED. For each declared ordering supersession, bind the complete baseline/target assertion lines, ordered JSON `inputLiterals`, `assertionForm` (`call` or parameter-row `sequence`), `expectedOperandIndex`, the single before/after expected literal, and the target ordering case/scenario marker. A `call` must be assertion-like and invoke the declared seam from a non-expected operand. A `sequence` must also declare an unchanged one-line `consumerLocator` that invokes the public or constraint seam. Every input literal must occur once, in order, outside and before the expected operand. The target assertion description may differ from the Git baseline only by that one expected operand, but the actual regression file must remain byte-identical to Git baseline; deleting a test, applying the described replacement locally, inserting control flow, weakening it to a tautology, or touching any other baseline content is rejected. Put executable proof scripts only under `.behavioral-regression/<id>/`, outside project test discovery. Run a directly relevant, unaffected project-test slice as the compatibility invariant and bind its files in that case's `protectedPaths`. Do not place a superseded assertion in `surface.preserves` or the compatibility invariant.
6. Define exactly four cases: one primary, two challenges in distinct dimensions, and one compatibility invariant. The primary and both challenges must share one isolated `proofPath` and exact direct command; bundle their arities, component interactions, and ordering scenarios in that single executable. For a merger generalized to zero/one/two/many inputs, exercise both the public and constraint seams at those arities so a public zero/one-input bypass cannot evade normalization, representation, or deduplication. The compatibility invariant runs the selected unaffected project-test slice separately and must state concrete preserved behavior; “the suite remains green” is execution status, not an oracle assertion. Bind every case to an oracle and structured `coverage` tokens. A seam token is valid only when the shared proof contains the declared locator. For a multi-component or variadic representation seam, choose the evidence model before authoring cases: independently meaningful positions use the asymmetric component matrix below; named components that the domain permits to degenerate only together use `surface.interactionModel: "coupled-boundary"` and one source-bound all-degenerate result witness; a truly homogeneous aggregate where empty contributors are neutral may use `homogeneous-neutrality`, `surface.components: []`, and prove `F(P) == F(E, P) == F(P, E)`. Do not use `coupled-boundary` to skip a partial input that the public seam actually supports. For matrix evidence, name at least two concrete argument positions in `surface.components` and one real call form's `dataComponents`; `slot-0`/`slot-1` are valid when positions are homogeneous in type but independently meaningful. Freeze every raw input in `componentSamples`; every partial case must reuse the all-degenerate case's exact sample for the component under test. For each relational preserved peer, add an `oracle.relations` entry of kind `value-and-representation` with a non-degenerate `sourceSample`, the independently expected `targetSample`, and a direct causal chain: `componentArguments` maps every logical component to a distinct bare identifier passed exactly once as a top-level argument by `invocationLocator`; `resultBinding` names that direct invocation's assigned result; `targetObservation` is only a property/index projection from that result; and `witnessLocator` passes the exact original invocation argument plus that projection. Between invocation and witness, do not call the seam again, rebind a component, or reassign/mutate the result. After the direct comparison succeeds, print exactly one structured witness containing the complete component matrix or coupled input/result payload. A bare marker, fallback expression, duplicate marker, or target taken from a separate populated call is not evidence. Create and run the bundle once before writing the contract, so syntax, module loading, and real seam calls are already known to work. After the diagnostic budget is exhausted, this pre-contract run must be one direct command targeting an existing file under `.behavioral-regression/BR-<id>/`; chaining, redirects, inline code, runner/environment hijacking, and production writes from the proof are blocked. If the shared bundle declares failure BEFORE, it must exit non-zero while the reproduction is present; printing a failure marker and exiting zero cannot issue a failure receipt.
   `coupled-boundary` is fail-closed: the original task must explicitly say that the named components degenerate together or that partial-degenerate inputs are invalid. A joint-empty example alone is not an exclusion rule. Without that explicit task evidence, use `component-matrix` and exercise each component empty while its peer remains populated.
   After three denied shell retries, terminal recovery accepts only this required Skill, a managed proof/contract write, or that one direct proof command. The Skill call does not consume another recovery attempt. Each other denied action advances the recovery counter; denial four supplies the exact platform file-writing tool card and denial five adds a blocking contract. Do not search, read unrelated files, dispatch agents, invoke unrelated skills, or write ordinary tests until the proof workflow advances.
7. Activate the hard workflow by writing or editing the valid contract with a file tool. Loading this Skill alone never activates hooks.
8. Run every declared command directly and exactly as stored. Do not wrap it with pipes, redirects, shell connectors, backticks, or command substitution. The hook tolerates only a trailing diagnostic `; echo "name=$?"` and restores its underlying exit status; prefer the exact command.
9. Copy only hook-issued `BR-R*` ids into matching `receipts.before` fields. A failure proves RED only when its literal signature is present; a timeout or missing command proves nothing.
10. On Claude, a high-risk contract now requires a real independent oracle reviewer before the first production write. High risk is derived when the surface has ordering or concurrency, three-or-more composition, multi-component input, or variadic representation. Dispatch one read-only subagent with a prompt containing only `BR_REVIEW_REQUEST <contract-id> oracle`; the lifecycle hook binds the next `SubagentStart` reservation even when that host event omits the original prompt, then injects the latest original user task, bounded claims, answer-free challenge inputs, exact evidence paths, and result schema. The original task is authoritative. Do not give the reviewer the proof bundle, implementation proposal, candidate oracle outputs, or your conclusion. The reviewer must use Read/Grep on every exact evidence path, derive each challenge result and a distinct contrasted shortcut independently, attempt a concrete counterexample, and echo the complete anchor set. For a machine-checkable challenge, follow its answer-free `valueShape` field and replace the `null` result placeholders with native raw JSON values of that field/type structure; never wrap an array or object in explanatory prose. Ordering cards retain the policy names but not their output: `stable-topological-layers` freezes all current indegree-zero nodes, emits that whole layer in first-seen order, and only then unlocks the next layer; `eager-first-seen` admits newly unlocked nodes after each individual removal. Return exactly one `BR_REVIEW_RESULT` as the final non-empty line. Every rejected attempt receives a recovery card with the same frozen inputs and no oracle answers, so correct that card rather than guessing another input. The hook mechanically recomputes conforming ordering and declared-supersession results; copied challenge ids or prose-only approval cannot issue a receipt. Oracle-stage disposition compares the independent derivation with the contract oracle, never with the intentionally defective baseline implementation: use `contract-conforms` when the derivation matches the contract even while baseline code fails. Only if the independently derived oracle itself disagrees should you return `contract-conflicts`, keep that result in `derivedExpected`, provide a same-shaped independently rejected alternative distinct from it in `rejectedAlternative`, and use decision `challenge`; do not guess or echo the hidden contract oracle. Reuse an approval while its plan, verification, and production fingerprints remain current; the hook rejects redundant dispatch. Codex currently lacks the complete dispatch/start lifecycle, so this review is advisory there and deterministic contract gates remain authoritative.
   For machine results, `valueShape` applies only to `derivedExpected`, `contrastValueShape` only to `rejectedAlternative`, and patch-stage `observedValueShape` only to `observedActual`; never copy one slot's shape into another. When a challenge includes `representationGrammar`, encode source-derived container names, nesting, and lengths with that exact answer-free grammar. Apply source-language semantics (a Python bracket comprehension is a list; a NumPy slice is an array), and make the JSON value mirror every descriptor length. Equivalent prose is not the same machine value. For coupled-boundary, apply it to both results; the contrast must match its advertised value shape but does not require guessing an author-selected hidden representation label.
11. Change only the declared production files. Use observable file-edit tools for production changes; an inline shell writer cannot bypass an incomplete BEFORE gate. Do not weaken, relocate, wrap, or otherwise replace verification assets after the first BEFORE receipt.
12. Run every declared command again. Copy fresh hook-issued ids into matching `receipts.after` fields.
13. Before closing a high-risk Claude contract, dispatch a different read-only subagent with only `BR_REVIEW_REQUEST <contract-id> patch`. It independently inspects the current production diff and fresh evidence, tries to falsify the patch, and returns the injected result card. The hook binds approval to the current plan, verification bytes, production fingerprint, and distinct agent id; any later production change invalidates it.
14. Set `status` to `closed` only after all case receipts and any required patch-review approval are present and Stop accepts the current production fingerprint. `paused` or `aborted` may release Stop at an untouched baseline with a concrete recovery action, but they keep declared production paths write-protected and cannot release after production changes. Reopen the next epoch and rebuild the required evidence before continuing edits; finish the evidence loop or restore the baseline first. A local oracle, test, review, or plan conflict is a replan signal, not an external blocker.

For v10 preserved-peer relations, `targetObservation` must select the complete output component with exactly one immediate property or index selector on `resultBinding`. Nested metadata such as `.shape`, `.ndim`, `.length`, or `.size` cannot stand in for the peer value. This observation rule does not require identity: an independently derived transformation such as `[2]` to `[6]` remains valid.

## Case selection

Use observations, not implementation guesses. Choose challenge dimensions that can falsify a superficially correct patch:

- `boundary`: empty, minimum, maximum, adjacent, or partial inputs.
- `representation`: alternate encodings, aliases, normalization forms, or serialized shapes.
- `composition`: behavior when combined with another supported operation.
- `ordering`: different valid sequences or deterministic ordering requirements.
- `error-contract`: error type, code, message shape, or failure timing.
- `state-transition`: before/after state and repeated transition behavior.
- `concurrency`: interleaving, retry, idempotency, or shared-state behavior.
- `compatibility`: an existing supported behavior that must remain unchanged.

For `component-matrix`, cover all populated, all degenerate, and a separate `oracle.kind: relational` case for each position alone being degenerate. Never combine both one-degenerate relations into one case. Every interaction case has `componentSamples` keyed by all components. For `coupled-boundary`, cover all populated plus one boundary case with every component degenerate, no preserved peers, `coupled-boundary` coverage, and an `oracle.coupledBoundary` object. Its `componentArguments` bind distinct identifiers used exactly once by one assigned direct seam call; `witnessLocator` passes the marker, those original arguments in surface order, and `resultBinding`. Freeze distinct `expectedSample` and `rejectedAlternative`, then print `<marker> {"components":<componentSamples>,"actual":<same-call result sample>}` exactly once. Empty-container all-degenerate values must be structurally empty; `[0]`, `[false]`, and `[null]` are not empty. A coupled contract must not contain `each-one-degenerate`; if one component can legally degenerate while peers remain populated, use the matrix.

For a public callable that accepts or aggregates a variable number of contributors, test that callable—not only a new helper—with zero, one, two, and many contributors. Put these arities in one boundary proof/case unless they require different setup. Preserve its observable return representation and warning or error contract unless the requested behavior explicitly changes them.

When a defect appears only after three or more sources are combined and pairwise intermediate output invents constraints absent from the original sources, set `compositionDepth` to `three-or-more` and `repairMode` to `extend-existing-seam`. The `constraint-seam` + `arity-many` case must call that existing seam directly and transition RED to GREEN. Extend the existing seam and route its consumers through it; a parallel variadic helper does not satisfy this proof while the original seam remains binary.

For ordering, set `surface.orderingPolicy` to `stable-topological-layers` and bind all six `oracle.scenarios` kinds: `independent-pair`, `independent-chains`, `shared-prefix`, `shared-suffix`, `duplicates`, and `genuine-cycle`. `scenarios` is never a contract-root field: place it only at `cases[i].oracle.scenarios`. Keep all six in one ordering challenge case and one proof command unless the runtime makes that impossible. Each scenario declares 2–8 contributor sequences, an exact expected order plus diagnostics, a marker, a witness locator, and an `invocationLocator` that calls the declared `surface.constraintLocator` through one opaque zero-argument thunk. The observation helper may receive that thunk only, never contributors it could use to synthesize diagnostics. `genuine-cycle` additionally declares the v11 `diagnosticProjection` described in the contract reference and returns an identity projection of captured warning messages or of the same seam result's canonical diagnostics field. `independent-pair` uses exactly two disjoint, duplicate-free contributors of at least two distinct items and proves that the policy applies at binary arity. `independent-chains` uses at least three pairwise-disjoint, internally duplicate-free contributors and at least one chain of three distinct items; this forces the proof to distinguish an atomic ready layer from an eager implementation that releases and selects a successor before the current layer is complete. `duplicates` means a value repeats anywhere within or across contributor sequences. The validator independently derives each topological layer, emits its ready items in first-seen order, and only then admits newly unlocked items. It rejects a self-authored depth-first order and any invented helper API that bypasses the real seam. Runtime witnesses must have no diagnostics for acyclic scenarios and exact diagnostics for a genuine cycle. Bind an intentionally changed warning in that cycle scenario; use a compatibility assertion only when the task requires warning text to remain unchanged. Print the structured contributor/outcome witness only after the actual public or constraint seam has produced it.

The contract is the activation and evidence boundary. The Skill is process guidance; hooks provide receipt provenance and prevent a completion claim from relying on test weakening or stale GREEN.
