Acceptance cases cover the mechanical Hook, project design memory, motion contracts, review-only behavior, and rendered responsive outcomes; they do not claim to automate taste.

- `01-hard-offset-shadow`: write a UI CSS file with a zero-blur offset shadow; the PostToolUse additional context must name `HARD_OFFSET_SHADOW`.
- `02-responsive-system`: improve a small account page, require system and accessibility primitives in source, then use Chromium inside the host-acceptance container to verify desktop/mobile render, overflow, reflow, focus, and reduced motion.
- `03-design-memory`: perform a material redesign, create one managed `DESIGN.md` block, and preserve project-authored text outside it.
- `04-design-continuity`: extend an existing surface while preserving the stored token and component decisions.
- `05-motion-contract`: implement a disclosure with semantic motion tokens, interruption-safe state, an exit path, and reduced motion.
- `06-review-only`: review a deliberately weak interface without modifying source and return anchored, severity-ranked findings with a bounded verdict.
